# Haunted Hall screens: plan for a smooth GUI on KICK

Implemented in `ui/` (JUCE): `HHUiCommon.cpp` (assets, knobs, the shared screen
base, the editor), `HHMasterScreen.cpp`, `HHStepScreen.cpp`, `HHBrowserScreen.cpp`.
Positions come from `ui/HHLayout.h`, generated by `art_tools/layout.py`.

The screens are where a groovebox app usually stutters on embedded hardware,
not the audio. Live glows, blurs and full-screen redraws are the usual cause.
This plan keeps the look of the mockups while drawing almost nothing per frame.

## The three screens

**MASTER**: four channel strips (DRUM, SYNTH A, B, C) with ON, MUTE and a
LEVEL meter; the 4-channel line mixer faders; the master delay with BYPASS and
a time readout. Hardware knobs: TIME, FEEDBACK, MIX, LEVEL.

**DRUM / STEP**: the 5-row grid (KICK, SNARE, HAT, GHOST, FX) x 16 steps, with
bar pages, the 8/16-bar switch, pattern A/B and RANDOM (the one-click
generator, with its style). Hardware knobs: DECAY, TONE, SPOOK, SPACE.

Every control maps to `PatternEditor` (engine/HHGrid.h):

| On screen | Call |
|---|---|
| tap a step | `toggleStep` |
| long-press a step | `cycleStep` (normal > accent > soft > off) |
| bar buttons 1-16 (a dot when the bar has notes) | page the view; `barHasNotes` |
| 8 BARS / 16 BARS | `setBars` |
| A / B | `Engine::requestPattern` (switches at the pattern end) |
| RANDOM | `randomize` (unlocked rows and the lane) |
| padlock beside a row name | `toggleRowLock` |
| CLEAR / COPY / PASTE | `clearBar`, `copyBar`, `pasteBar` (a bar = drums + melody lane) |
| UNDO (long-press: REDO) | `undo`, `redo` (32 steps) |
| long-press RANDOM | next groove style |
| long-press CLEAR / COPY / PASTE | the whole pattern |
| the top banner | back to MASTER |
| MELODY strip | shows the lane's notes; `transposeLane`, `clearLane` |
| playhead | `Engine::currentStep` |

**CARTRIDGE BROWSER** (one per layer): the large cartridge picture, the theme
carousel, 10 presets per page, RANDOM, FAVORITE, LOAD, BACK. Categories:
Drum / Bass / Lead / Pad. Hardware knobs: that layer's DECAY, TONE, SPOOK,
SPACE, shown in a slim strip on this screen.

## Changes from the mockups

- **Drum 20 % limit**: it's the drum layer's delay send, not its fader. The
  drum fader works like the others. Label the drum SPACE knob "DELAY MAX 20 %"
  and remove "DRUM MAX 20 %" / "OUTPUT CAP 20 %" from the fader.
- **Transport**: PLAY / STOP / LOOP duplicate KICK's hardware buttons. Remove
  them and use the space for bar pages, 8/16 bars and pattern A/B.
- **Step screen**: use the 5-row Step Mode mockup (with FX).
- **Browser**: use the lavender cartridge version with the theme carousel.
- **Names**: rename "Retro Moog" (a brand name), e.g. "Retro Ladder".
- **Synth knob strip**: add a slim DECAY / TONE / SPOOK / SPACE strip to the
  browser screen so each synth layer has a home for its knobs.

## Art: what to ask for

Ready-to-paste prompts are in `ART_REQUESTS.md`. In short, ask for the art in
layers, with everything that changes left out:

1. One **background per screen** with all frames, glows, graveyard trim,
   static labels and static icons baked in. No lit steps, no knob pointers, no
   fader caps, no meter fill, no changing text.
2. **Cartridge pictures** as pixel art at their native size (about 96 x 96),
   one per theme: haunted castle, skeleton, haunted organ, alien saucer, night
   racer, boss dragon, crystal sword, platform block, flying ghosts.
3. **Sprite sheets** for small animations: the ghost (8 frames, about 64 x 64),
   bats, the decrypting bar, the glitch pixels by the cartridge.
4. **Small parts**: a lit and an unlit step cell, a fader cap, a knob cap
   without its pointer, the ON / MUTE / BYPASS states.

## Drawing rules

| Rule | Why |
|---|---|
| Bake every glow, shadow and texture into the images | Live blur and glow effects are the most expensive thing a screen can do |
| Repaint only what changed: a step cell, two playhead columns, one knob, one meter | A full 1024 x 600 redraw every frame is what makes screens stutter |
| Animate sprites at 15-20 fps from one shared timer, each in its own small rectangle | Smooth enough for pixel art, a tiny fraction of the cost |
| Store pixel art at native size; scale with nearest-neighbour (low resampling quality) | Crisper, and a 96 x 96 picture costs 36 KB instead of megabytes |
| Knobs: a static cap image plus a vector pointer and arc | No rotated-image resampling |
| Mark solid components opaque | The framework can skip drawing what's behind them |
| Bake static text into the backgrounds; one pixel font for the rest | Text layout is surprisingly costly |
| The screen reads the engine's atomics (step, pattern, meters) at about 30 Hz | No locks between the screen and audio |

## Memory budget

| Asset | Decoded size |
|---|---|
| 3 backgrounds at 1024 x 600 | about 7.4 MB |
| 9 cartridge pictures at 96 x 96 | about 0.3 MB |
| Sprites and small parts | under 1 MB |
| Engine (audio) | about 1.2 MB |

Load all of it once when Haunted Hall opens, never during playback.

## Target

Each screen update should take under 4 ms on KICK, measured in the simulator
and then on the device. The playhead moves at most about 11 times per second
(16ths at 160 BPM), so the step screen mostly sits still.
